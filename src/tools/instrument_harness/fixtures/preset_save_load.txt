# Fixture: preset save / overwrite-modal / load-list flow.
#
# Exercises the three stateful preset pathways through the instrument_harness
# under Xvfb. Drives the live input by injecting key presses into the harness
# event queue (one frame per script line by default), so behaviour is identical
# to a real user typing on the keyboard.
#
# NOTE: the script engine parses ONE step per line (tokens[0] is the op);
# multi-key lines only run the first key. So every key is on its own line.
#
# Initial state after initApplication():
#   - selection = RATIO1 (FM instrument, btnrow1)
#   - bank      = fm1..fm5 (5 presets seeded from bin/data/instrument_presets/)
#   - algo      = 0, all FM params at default values
#
# Layout reminder for btnwrap ("PRESET_CONTROLS" row, horizontal):
#   [PRESET, pad1, PRESET_NAME, SAVE, LOAD]
# `pad1` is a blank non-selectable spacer; selectAdjacent skips it, so
# horizontal navigation compresses to PRESET -> PRESET_NAME -> SAVE -> LOAD.

# --- Navigate from RATIO1 to PRESET_NAME ---------------------------------
# UP from a horizontal item walks the searchUpwardsByAlignment ladder to the
# nearest vertical container's previous sibling. From btnrow1 -> btnwrap ->
# instwrap, the previous item is presetWrap, and selectLeaf(g, presetWrap,
# head=false) lands on the TAIL of PRESET_CONTROLS = LOAD.
UP
ASSERT selected==LOAD

# Two LEFTs slide LOAD -> SAVE -> PRESET_NAME.
LEFT
LEFT
ASSERT selected==PRESET_NAME

# EDIT to start editing. Arrows only cycle while editing.

# Task 4: explicit EDIT to exit edit mode before commit. The "not editing"
# START branch handles the commit + overwrite check (matches the previous
# auto-edit -> START flow, which also left editing=false on commit).
EDIT

# --- Save the new preset (creates a brand new bank slot) -----------------
# START at PRESET_NAME commits the edit and runs guiSavePreset. "Xm1" does
# not exist yet, so saveInstrumentAsPreset returns PRESET_SAVED -> adds the
# patch to the bank and writes bin/data/instrument_presets/Xm1.ipb.
START
ASSERT preset==Xm1
ASSERT file==Xm1
ASSERT presetCount==6
ASSERT savedFlash==1

# --- Re-save with the SAME name to trigger the overwrite modal -----------
# guiSavePreset calls saveInstrumentAsPreset, which returns PRESET_EXISTS
# for "Xm1" (already in the bank). guiSetOverwritePending flips the modal
# into MODAL_CONFIRM_OVERWRITE; the next frame's input handler intercepts
# LEFT/RIGHT/START/SELECT before any other code can run.
START

# --- Drive the modal: NO is the safe default, so flip to YES ------------
# LEFT (or RIGHT) toggles g_overwriteChoice. The display shows NO red by
# default; one LEFT highlights YES red instead.
LEFT

# START commits. saveInstrumentAsPresetOverwrite replaces the existing bank
# slot at "Xm1" without growing presetCount, so the count stays at 6.
START
ASSERT presetCount==6
ASSERT preset==Xm1
ASSERT file==Xm1

# --- Re-save to reopen the modal, then CANCEL (SELECT) ------------------
# The name node is still selected + editing after the overwrite. Committing
# "Xm1" again reopens the modal; SELECT cancels it (modal closes, no
# overwrite happens, bank + file untouched).
START
SELECT
ASSERT presetCount==6
ASSERT preset==Xm1
ASSERT file==Xm1

# Task 4: edit mode is already off after the prior commit (commitPresetName
# sets editing=false before the modal opens). This SELECT is a no-op now --
# the not-editing branch consumes KM_SELECT without changing state. Arrows
# navigate again because the not-editing branch returns false for them.
SELECT

# --- Open the load list --------------------------------------------------
# DOWN from PRESET_NAME drops out of btnwrap -> presetWrap -> FM instwrap,
# and selectLeaf(g, FM instwrap, head=true) lands on RATIO1 (btnrow1 head).
DOWN
# UP from RATIO1 walks back the same ladder and lands on LOAD (tail of
# PRESET_CONTROLS) -- same path used in step 1.
UP
ASSERT selected==LOAD

START
ASSERT loadListActive==0

# Sanity: the saved file is still on disk after load.
ASSERT file==Xm1
